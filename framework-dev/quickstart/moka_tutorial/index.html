    Tutorial: a simulated AO loop with moka¶

    From two example confdirs to an AO loop closed on simulated turbulence, with moka and the milk TUIs.

    Audience: Operator · See also: Installation · moka · Operating · fpsCTRL Reference · pyMilk

    At the end of this page, your screen looks like this:

    The desktop with the loop closed on turbulence; the numbers are explained below.

    # Window Shows
    1 milk-fpsCTRL Engineering control of all compute units. Arrow keys and keyboard.
    2 milk-streamCTRL Framerate, counters and symlinks of every stream on the machine.
    3 shell moka working shell.
    4 shell Second shell, for the viewers.
    5 shmImshow dm07disp Total DM output.
    6 shmImshow dm07disp03 AO loop output.
    7 shmImshow dm07disp10 Turbulence (FPS mlatsim_dmturb).
    8 shmImshow aol0_psf PSF of the DM phase (dm_psf.py).
    9 shmImshow aol0_imWFS0 PyWFS frames, as acquired.
    10 shmImshow aol0_imWFS2 WFS frames: dark subtracted, normalized, reference subtracted.

    You run two pipelines. mlatsim simulates a DM, a pyramid WFS and its camera; aoloop is the AO loop. The delaysim linkage of aoloop connects them: the loop reads the simulated camera and writes into one channel of the simulated DM.

    flowchart LR
    subgraph mlatsim
        dmturb --> |dm07disp10| dmcomb
        dmcomb --> |dm07disp| dmdelay --> pywfs --> wfscam
    end
    subgraph aoloop
        acquWFS --> wfs2modes --> mfilt --> modes2dm
    end
    wfscam -. "mlatsim_wfs = aol0_wfsim" .-> acquWFS
    modes2dm -. "aol0_dmC = dm07disp03" .-> dmcomb

    The page takes 30 to 45 minutes. Nothing touches hardware: every process runs on your machine.

    1. Before you start¶

    Check that milk, cacao, moka and tmux are installed and that the environment is set.

    moka -h | head -3
echo MILK_ROOT=$MILK_ROOT; echo MILK_INSTALLDIR=$MILK_INSTALLDIR; echo MILK_SHM_DIR=$MILK_SHM_DIR; echo MILK_PROC_DIR=$MILK_PROC_DIR
ls -d "$MILK_ROOT"/milk-examples/pipelines/{mlatsim,aoloop}-conf
which cacao-fpsexec-mfilt milk-fpsexec-linalg-MVMextract milk-fpsCTRL milk-streamCTRL milk-termview shmImshow
tmux -V
python -c 'import moka, pyMilk, matplotlib, numpy; print("ok")'

    When a check fails

    • moka or a python import missing: Installation §4. shmImshow comes with pyMilk's vis extra.
    • An empty variable: Installation §2.
    • No milk-examples/pipelines: MILK_ROOT must point to the milk source tree. mokainit clone --milk copies the example confdirs from there.
    • A which line missing: milk or cacao is not installed in $MILK_INSTALLDIR, or its bin/ is not on your PATH.

    Look around

    Ask moka. Every command has --help: moka --help, moka deploy --help, mokainit --help, mokashow --help (mokashow has no -h).

    2. Set up your screen¶

    Open four terminals, arranged as in the image at the top: two TUIs on the left, two shells below them. Start the TUIs:

    milk-fpsCTRL     # (1)!
milk-streamCTRL  # (2)!
    1. In the first terminal: every FPS on the machine.
    2. In the second terminal: every stream on the machine.

    Both are empty for now.

    milk-fpsCTRL before any deploy.

    milk-streamCTRL before any deploy.

    Look around

    Leave both TUIs open for the whole page: each stage below changes what they show. In either one, h shows the keys and x quits. The third terminal is your moka working shell, the fourth is for the viewers.

    3. Get the two confdirs¶

    Copy the example confdirs mlatsim-conf and aoloop-conf into a new working folder.

    mkdir ~/AOloop2
cd ~/AOloop2
mokainit clone --milk mlatsim .
mokainit clone --milk aoloop .
find mlatsim-conf aoloop-conf | sort

    Look around

    Under the hood. Open aoloop-conf/conf.toml: the [compute_units] table names one milk or cacao executable per compute unit, runstart lists those that moka runstart starts, and [systemlinkage.delaysim] maps the loop's streams onto the simulator's. The FPS values are in fpsdetails.toml, included by conf.toml.

    Change the configuration. A confdir is what you edit and keep in git; nothing on this page edits it until §14. See Configuration.

    4. Build the rootdirs¶

    Check each confdir, then build its rootdir: the home of one pipeline instance.

    mokainit resolve mlatsim-conf > /dev/null  # (1)!
mokainit resolve aoloop-conf > /dev/null
    1. Prints the resolved configuration: includes merged, substitutions done. Drop the redirection to read it.
    mokainit init mlatsim-conf
mokainit init aoloop-conf
find mlatsim-rootdir | sort
moka state -p aoloop

    What moka did

    init ran the hooks of mlatsim-conf, which generate the initial DM, camera and pupil files into mlatsim-conf/data/, then copied conf files and hook products into the rootdir (conf/, initdata/). From now on only the rootdir matters.

    Two lines come back at every moka call on aoloop, and are expected: INFO: ... extra keys ['_ln'] (_ln is an alias that conf.toml defines for substitution) and WARNING: Local plan 'takedark' overrides another one. (see §7). mokainit prints the first one only.

    Look around

    Ask moka. moka state -p mlatsim: cold, nothing is deployed. moka plans -p mlatsim lists every plan and whether it can run now: deploy is ok, and the plans that need acquWFS or mfilt (mlat, measlinresp, takeref, spool) show n/a (Unknown compute units ...).

    The -p rule. -p aoloop means ./aoloop-rootdir. Inside a rootdir, leave -p out: cd mlatsim-rootdir && moka state. Elsewhere, moka state without -p fails with [FAIL] ... is not a rootdir.

    6. Deploy the loop and link it¶

    2. Applies [systemlinkage.delaysim]. It prints no step line.

    from pyMilk.interfacing.shm import SHM

wfs = SHM("aol0_wfsim")
print(wfs.shape, wfs.get_data().mean())

    Ask moka. fpsCTRL now lists 11 FPS. moka state -p aoloop: configured.

    What moka did

    takedark here is not the built-in plan. aoloop-conf/scripts/moka_plans.py defines a local one that wraps it: RemoveLightSim sets the simulated camera's flux to 0, TakeDark averages frames into aol0_wfsdark, PutbackLightSim restores the flux. The dark needs only the linkage that gives aol0_wfsim its data. takeref starts acquWFS, then averages its aol0_imWFS1 frames into the reference.

    In the fourth terminal, open the WFS frames as acquWFS reads them, and as the loop uses them. Two viewers show a stream: shmImshow opens a window, milk-termview draws in the terminal itself. Use either; the stream images below are milk-termview captures.

    shmImshow aol0_imWFS0 &
shmImshow aol0_imWFS2 &

    Or, one stream per terminal:

    milk-termview aol0_imWFS0  # (1)!
    1. q quits, c cycles the colormaps, -h lists the keys.

    aol0_imWFS0: the camera frame, four pupil images.

    aol0_imWFS2: with the DM flat, the frame minus the reference is noise around zero.

    Look around

    Ask moka. moka plans -p aoloop marks takedark (local, overrides built-in) and shows its three steps.

    Under the hood. ls aoloop-rootdir/calib: wfsdark.fits, wfsref.fits. -n NFRAMES or -t SECONDS sets how much is averaged.

    If takedark stops midway, the simulated light stays off (mlatsim_wfscam.fluxtotal is 0 in fpsCTRL). Run moka takedark -p aoloop again: it puts the light back.

    Change the configuration. The step amplitude is OPDamp of [compute_units.mlat.fps] in aoloop-conf/fpsdetails.toml.

    10. Compute the control matrix¶

    Invert the response into the matrices that turn WFS frames into mode values and mode values into DM commands, keeping at most the first 155 modes.

    moka mkcm -p aoloop -n 155 -r 1e-3  # (1)!
    1. -n 155 keeps at most the 155 strongest singular modes of the response: the WFS sees only the 156 actuators lit by the pupil of mlatsim (mlatsim_pupmask), out of the 208 of the DM mask, and piston, which the WFS cannot measure, is dropped. -r 1e-3 also drops the modes whose singular value is below 1e-3 of the strongest. The other modes are noise to the WFS; without the cut, the loop is unstable and corrects badly.
    Output 
    INFO: ~/AOloop2/aoloop-rootdir/conf/conf.toml: extra keys ['_ln']
WARNING: Local plan 'takedark' overrides another one.
> moka mkcm
rootdir: ~/AOloop2/aoloop-rootdir
aoloop: mixed
  [1/1] MakeCM ... [ ok ] done (0.3 s)
[ ok ] mkcm done in 0.3 s

    mokashow cm -p aoloop

    The control matrix: a control mode, and the singular values of the response with the -n cut.

    The singular values drop past mode 155, where -n 155 cuts.

    Look around

    Change the configuration. Without -n, mkcm keeps every mode, the ones the WFS does not see included. moka mkcm -p aoloop tikhonov -r 0.01 regularizes instead of cutting. Options: Plans and tasks §1.

    Ask moka. mkcm touches no stream: moka plans -p aoloop shows it ok even on a cold pipeline.

    In fpsCTRL, the aoloop_mfilt FPS holds the loop parameters. loopON is OFF:

    Ask moka. moka state -p aoloop: running, every compute unit of runstart runs.

    Under the hood. In streamCTRL, aol0_modevalWFS (mode values measured) counts at the camera rate; aol0_modevalDM (mode values sent) stays at 0 while loopON is OFF. milk-fpsCTRL -n aoloop_mfilt opens fpsCTRL on that FPS alone.

    12. Close the loop¶

    Turn the integrator on.

    In the fpsCTRL window:

    1. select aoloop_mfilt with the Up and Down keys;
    2. press Right to show its parameters, then Down to loopON;
    3. press Space: loopON turns ON.
    from pyMilk.interfacing.fps import FPS

mfilt = FPS("aoloop_mfilt")
mfilt["loopgain"] = 0.2
mfilt["loopmult"] = 0.99
mfilt["loopON"] = True

    The loop closed: loopON is ON.

    There is nothing to correct yet, so the loop output stays close to zero (a few thousandths of a µm). Watch it in the fourth terminal:

    shmImshow dm07disp03 &

    dm07disp03, the loop closed with no turbulence: small values around zero.

    Look around

    Play with the loop. Press Space on loopON again: the loop freezes, dm07disp03 keeps its last command. loopZERO (Space) zeroes the command. Close the loop again before going on.

    13. Add turbulence and watch the PSF¶

    Start the turbulence generator of mlatsim and turn it on, then compute the PSF of the DM.

    moka runstart -p mlatsim dmturb
    Output 
    > moka runstart

    In the fpsCTRL window, select mlatsim_dmturb, show its parameters, move to turbON and press Space.

    The turbulence generator: turbON, ampl, wspeed.

    The turbulence shows on dm07disp10 about 2 s later. Compute the PSF of the DM in a tmux session:

    tmux new-session -d -s dm_psf "python aoloop-rootdir/conf/scripts/dm_psf.py"  # (1)!
    1. Writes the PSF of dm07disp to aol0_psf ten times a second, until §15 stops it. tmux a -t dm_psf shows its output.

    In the fourth terminal, open the viewers of the image at the top:

    shmImshow aol0_psf &
shmImshow dm07disp10 &
shmImshow dm07disp &

    dm07disp10: the turbulence written by mlatsim_dmturb.

    With the loop closed, dm07disp03 cancels dm07disp10 inside the pupil: there dm07disp, their sum, is flat. The PSF is sharper than with the loop open, shown next.

    dm07disp, the loop closed: flat inside the pupil, the turbulence left outside it.

    aol0_psf, the loop closed.

    To see the open loop, set loopON to OFF, then loopZERO:

    import time

from pyMilk.interfacing.fps import FPS

mfilt = FPS("aoloop_mfilt")

    dm07disp, the loop open: the turbulence alone.

    aol0_psf, the loop open.

    Close it again with loopON:

    from pyMilk.interfacing.fps import FPS

FPS("aoloop_mfilt")["loopON"] = True

    Open loop

    loopON OFF freezes the correction, it does not remove it; loopZERO removes it.

    Mask of the PSF

    dm_psf.py computes the PSF over the DM mask ([dmhint], 208 actuators), while the WFS sees 156 of them: the loop leaves the ring outside the pupil uncorrected, which limits the gain in the PSF. Masks can be made from the control matrix; this page will be amended when that is done.

    Look around

    Play with the loop. On aoloop_mfilt, edit (Enter) loopgain and loopmult; on mlatsim_dmturb, ampl (the configured amplitude, rms in µm) and wspeed (m/s). Watch the PSF and dm07disp03 after each change.

    • The loop diverges from a loopgain of about 0.6; with loopmult at 0.999 or 1.0 it diverges slowly.
    • looplimit limits each mode, not the total: it does not stop a divergence.
    • To recover: loopON OFF, then loopZERO, then a lower gain and loopON again.

    Under the hood. Read the loop from Python while you play:

    from pyMilk.interfacing.shm import SHM

for name in ("dm07disp10", "dm07disp03", "dm07disp"):
    print(name, SHM(name).get_data().std())

    Change the configuration. Values set in fpsCTRL last until the next deploy. To keep a turbulence amplitude, change ampl in mlatsim-conf/conf.toml, as §14 does for loopgain.
