# R6: pyMilk boundary

Feature directory: `specs/009-r6-pymilk-boundary` (number it in the order you actually run it) · Tests: milk

## /speckit-specify

```text
Feature directory: specs/009-r6-pymilk-boundary
Parent roadmap: specs/pipelines/ROADMAP.md → entry R6. Design: specs/pipelines/design-v7.md (§2.3, §4.5, D-13).

Give the milk package one narrow, tested seam to pyMilk.

Why: milk imports pyMilk from several places, config validation pulls the native ImageStreamIOWrap just to check a stream name, and pyMilk's vendored copy of the milk engine can drift from the installed milk ("got burned again" in WORKLIST.md).

Requirements:
- Every use of pyMilk goes through one interface module: FPS read/write, SHM create/check, and the SHM directory.
- SHM-name validation used by config validation is pure Python, so resolving a config never imports native bindings.
- A contract test fails, with a message naming both versions, when the ImageStreamIO/FPS ABI version of the milk install differs from the one pyMilk was built against.
- pyMilk exceptions propagate unwrapped.

Out of scope: merging the repositories; changing pyMilk itself (if a version accessor is missing on the pyMilk side, stop and ask Vincent).

Success criteria: the suite is green; a search finds pyMilk imported only in the interface module; config resolution works with ImageStreamIOWrap unimportable; the contract test passes on a matched install and fails on a simulated mismatch.
```
